# ADR-001: Redpanda sebagai brokering stream tempatan (tanpa platform cloud)

- Status: Accepted
- Tarikh: 2026-11-21
- Pembuat: SkyPulse Data Platform Team

## Konteks
Projek memerlukan sumberBatch *dan* sumber stream dengan `event_time` dan `event_id` unik.
Spesifikasi tugas menetapkan platform mesti kekal On-Premise / local; managed cloud
tidak boleh menggantikan komponen teras. Kumpulan perlu repli, offset dan replay tanpa
bergantung kepada servis luar.

## Keputusan
Guna Redpanda (API Kafka) dalam Docker,.topik `flight-raw-stream` dan `flight-stream-dlq`,
dengan `acks=all`, `retries=3`, partition key = `icao24`. Producer juga menulis
`data/bronze/flight_events_raw.jsonl` sebagai *source of truth* sebelum publish.

## Alternatif
- Kafka + Zookeeper: lebih kompleks untuk demo satu mesin.
- Managed Kafka (Confluent Cloud): melanggar keperluan local-only.
- Polling API terus ke consumer: tiada replay/offset, sukar buktikan F-05/F-13.

## Kesan
+ Replay boleh dibuat dari Broker *atau* dari Bronze JSONL (`--replay-bronze`).
+ Konsumer menyimpan offset secara eksplisit dan dedup dalam SQLite.
- Operasi perlu memantau health broker dan saiz topic; resource limit 768 MB ditetapkan.
