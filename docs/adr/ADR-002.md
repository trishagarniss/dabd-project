# ADR-002: Parquet versi snapshot + PostgreSQL ACID untuk serving

- Status: Accepted
- Tarikh: 2026-11-21

## Konteks
Analitik memerlukan scan kolumnar yang cekap untuk jutaan baris, tetapi jadual serving
dan audit memerlukan konsistensi transaksi (upsert, primary key, role). Satu teknologi
sahaja tidak memenuhi kedua-duanya dengan baik.

## Keputusan
- `src/common/storage.py` menulis dataset Bronze/Silver/Gold sebagai **Parquet** dengan
  direktori `version=<timestamp>`, fail `*.parquet` semasa, dan `*.snapshot.json`
  (row_count + sha256 + columns + keys). Upsert menggunakan `updated_at` dan `keys`.
- PostgreSQL menyimpan jadual ACID di schema `bronze/silver/gold/ops` (DDL:
  `config/init_db.sql`) untuk mart serving, audit dan kawalan akses.

## Alternatif
- Postgres sahaja untuk semua layer: kos penyimpanan dan scan analitik lebih tinggi.
- Data lake cloud (S3/Delta): melanggar keperluan local-only.

## Kesan
+ Konsistensi update dibuktikan dengan snapshot checksum dan primary key SQL.
+ Backup boleh berasaskan manifest fail + `pg_dump`.
- Perlu menjaga Parquet dan DB segerak; keputusan ini didokumentasikan dalam
  `docs/RUNBOOK.md` dan alat `scripts/backup.py`.
