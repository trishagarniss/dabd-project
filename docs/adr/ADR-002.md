# ADR-002: Parquet dengan versi snapshot + PostgreSQL ACID untuk serving

- Status: Diterima
- Tanggal: 2026-11-21

## Konteks
Analitik membutuhkan pemindaian kolumnar yang efisien untuk jutaan baris, tetapi tabel
serving dan audit membutuhkan konsistensi transaksi (upsert, primary key, role). Satu
teknologi saja tidak memenuhi keduanya dengan baik.

## Keputusan
- `src/common/storage.py` menulis dataset Bronze/Silver/Gold sebagai **Parquet** dengan
  direktori `version=<timestamp>`, file `*.parquet` terkini, dan `*.snapshot.json`
  (row_count + sha256 + columns + keys). Upsert memakai `updated_at` dan `keys`.
- Retensi versi dibatasi `FDP_MAX_SNAPSHOT_VERSIONS` (default 5) agar aliran 15 detik
  tidak membuat `data/silver` dan `data/gold` membengkak.
- PostgreSQL menyimpan tabel ACID di schema `bronze/silver/gold/ops` (DDL:
  `config/init_db.sql`) untuk mart serving, audit, dan kontrol akses.

## Alternatif
- Postgres saja untuk semua layer: biaya penyimpanan dan scan analitik lebih tinggi.
- Data lake cloud (S3/Delta): melanggar kebutuhan local-only.

## Dampak
+ Konsistensi update dibuktikan dengan snapshot checksum dan primary key SQL.
+ Backup dapat berbasis manifest file + `pg_dump`.
- Perlu menjaga Parquet dan DB tetap sinkron; keputusan ini didokumentasikan dalam
  `docs/RUNBOOK.md` dan alat `scripts/backup.py`.
